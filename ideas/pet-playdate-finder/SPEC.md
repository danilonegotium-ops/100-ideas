# Pet Playdate Finder — SPEC

**MVP:** A logged-in user creates one or more dog profiles (name, breed, size, energy level, free-text neighborhood, optional bio). They browse other owners' dogs one at a time (optionally filtered to the same neighborhood text as the currently-selected dog) and swipe "Interested" or "Pass". A swipe is recorded per dog-pair with a direction (`yes`/`no`); when two dogs have both swiped `yes` on each other, it's a match, shown in a "Your matches" section for both owners. No in-app messaging — per the task, contact happens outside the app once matched.

**Match computation:** no separate `matches` table — a match is derived at query/render time from the `pet_playdate_finder_swipes` table: dog A and dog B match iff a `(A→B, yes)` row and a `(B→A, yes)` row both exist. Computed client-side in `components/PlaydateApp.tsx` over two small server-fetched sets (this user's outgoing swipes, and swipes incoming to this user's dogs) rather than a SQL join — simpler to get right without live-testing a cross-referencing join query, and correct at this data scale.

**Scope adaptations:**
- **Photo via URL only, not file upload.** `photo_url` is a plain nullable text column with no upload UI — adding real photo upload would need a Supabase Storage bucket + policies, which can't be meaningfully set up or verified without a live Supabase project. Noted here rather than silently dropped; straightforward to add a Storage-backed upload later without a schema change.
- **Incoming "likes" are visible before you reciprocate**, unlike real Tinder's blind-swipe mechanic (where you don't know who liked you until you also swipe yes). The task's spec doesn't ask for that specific hidden-likes mechanic ("simple swipe-like yes/no, match when both said yes" — no mention of hiding pending likes), and building it properly would need the same category of RLS-privacy design as `shared-wishlist`'s claim-hiding logic; scoped out as unnecessary complexity for this MVP. If wanted later, the RLS pattern from `shared-wishlist` is a direct template for it.
- **"Same area" filtering is a client-side substring/exact-match heuristic** over the free-text `neighborhood` field (no geocoding), matching the task's "browses other dogs in the same area" without adding a mapping dependency — a toggle lets you turn it off and see all dogs regardless of area.
- Multiple dogs per owner are supported (a small dog-selector toggles which of your dogs is doing the swiping) even though the task only requires one profile — natural fit for a multi-dog household, no extra schema cost.

**Schema (`schema.sql`):** `pet_playdate_finder_dogs` (owner, name, breed, size enum, energy_level enum, neighborhood, bio, photo_url) and `pet_playdate_finder_swipes` (from_dog_id, to_dog_id, direction enum `yes|no`, unique on `(from_dog_id, to_dog_id)` so a dog can't double-swipe the same target, check constraint preventing a dog from swiping on itself). RLS: dogs are browsable by any logged-in user (not public/anonymous — this is an account-gated social app) but only editable by their owner; swipes are visible to a user if they own either side of the pair (needed for both "don't re-show already-swiped dogs" and match computation) and insertable only for swipes originating from a dog you own. Seed: 8 demo dogs split across **two** placeholder demo-user UUIDs (not one) specifically so the match flow is demonstrable — one pre-seeded mutual match (Buddy ↔ Rex) plus several unswiped candidates for each demo owner. See the "Demo user note" at the top of `schema.sql` for what to do about those placeholder UUIDs once Supabase is live.

**What still needs a live Supabase project to verify end-to-end:** that the RLS policies behave as written under two different real logged-in users (the whole point of the two-demo-user seed setup — confirm logging in as demo user 1 shows the Buddy↔Rex match, and demo user 2 sees the same match from their side), and that the unique/check constraints on `swipes` behave as expected under concurrent swipes. `npm run build`, `npx tsc --noEmit`, and `npm run lint` all pass clean locally with empty env vars.
