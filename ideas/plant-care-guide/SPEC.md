# Plant Care Guide — SPEC

**MVP:** User picks a plant from a curated catalogue of 20 common houseplants (`data.js` — each with a base watering interval in days and light needs) and types their city. On "Add plant", the app geocodes the city name via Open-Meteo's free, keyless geocoding endpoint (`https://geocoding-api.open-meteo.com/v1/search?name=<city>&count=1&language=en&format=json`) to get lat/lon, then calls Open-Meteo's free, keyless forecast endpoint (`https://api.open-meteo.com/v1/forecast?latitude=..&longitude=..&current=temperature_2m,relative_humidity_2m&timezone=auto`) for current temperature and relative humidity. Both endpoints were confirmed by hand with `curl` before wiring them in — the "not found" case for geocoding returns a body with no `results` key at all (just `{"generationtime_ms": ...}`), which `geocodeCity()` handles explicitly. `adjustWateringInterval()` nudges the plant's base interval: humidity under 30% shortens it (water more often, soil dries faster), humidity over 65% lengthens it (water less often), and temperature over 30°C adds a small extra reduction; the combined factor is clamped to [0.6, 1.3] and the result is never less than 1 day. Each added plant becomes a card showing the location, live weather snapshot, base vs. adjusted interval, a "Water today / Water in N days / Overdue by N days" status, and the last-watered date. "Mark as watered today" resets the countdown. Everything (the tracked-plant list) is persisted in `localStorage`, so a user can track several plants across several cities at once.

**Out of scope for this pass:** actual push/email watering reminders (the original one-liner says "sends watering reminders" — no notification backend exists for a static, no-server tool; the countdown is shown in-page instead); forecasted/future humidity (only *current* conditions are used, not a multi-day trend); per-plant custom watering overrides (the interval is fully computed, not user-editable); light-level adjustment (only watering interval reacts to weather — light needs are shown as static guidance from the catalogue, not adjusted by anything measurable client-side).

**Data/content:** `data.js` has 20 hand-curated common houseplants with approximate base watering intervals and light needs, drawn from generally-cited houseplant-care norms (typical indoor pot size, average conditions) — explicitly a simplified starting point, not professional horticultural advice, and stated as such needs no citation of a single source since it's a synthesis of common general guidance. Weather data itself is live and real, from Open-Meteo (open-meteo.com), which is free and requires no API key or account for either the geocoding or forecast endpoint used here.
