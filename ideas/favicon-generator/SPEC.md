# Favicon Generator — SPEC

**MVP:** User picks a source image. It's drawn into an off-screen `<canvas>` once per target size (16, 32, 48, 180 [Apple touch icon], 192, and 512 px), using a centered "cover" crop so non-square source images don't get squashed — the crop math (`computeCoverCrop`) finds the largest centered square in the source and only that square is resized into the target square. Each size renders as a preview swatch (on a checkerboard background so transparency is visible) with its own `<a download>` link that saves a real PNG file via `canvas.toDataURL('image/png')`. A "Download all sizes" button fires each download in sequence with a small stagger so browsers don't block them as popups. Everything happens client-side; the image is never uploaded.

**Out of scope for this pass:** bundling all sizes into a single `.zip` (would need a zip library — out of scope for a zero-dependency static tool; individual downloads cover the same end result) or generating an `.ico` multi-resolution file (browsers/OSes now accept PNG favicons directly via `<link rel="icon">`, so PNG-only covers the modern use case); auto-generating the `<link>` tags/manifest snippet to paste into a site's `<head>` (a nice future addition, not required for the core "turn an image into favicon sizes" job).

**Data/content:** `SIZES` in `app.js` is the standard list of favicon/touch-icon/Android-icon dimensions used by modern browsers and OSes — not sourced from external data, just well-known conventions (16/32/48 classic favicon sizes, 180 Apple touch icon, 192/512 Android/PWA manifest icons).
