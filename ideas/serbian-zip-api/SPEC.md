# Serbian ZIP Codes API — SPEC

**MVP:** A dev-facing REST API, not an interactive UI. `GET /api/zip` (a Vercel Node.js
serverless function at `api/zip.js`) serves 1,155 Serbian postal-code records — postal code,
place name, admin subdivisions, lat/long — from a JSON file baked into the repo at
`data/rs-zip.json`. Supports `?code=` (exact postal code match) and `?city=` (case-insensitive
partial match on place name); no params returns a 50-record sample. No API key, no runtime
external calls (the dataset is static, fetched once at build time from GeoNames), CORS open.
`index.html` is API documentation only (endpoint, params table, curl examples with copy
buttons, example response, attribution) — matching the brief's request for a dev-product feel
rather than a search form.

**Out of scope for this pass:** pagination beyond `limit`/truncation flag, fuzzy/typo-tolerant
city search (exact substring match only), rate limiting (not needed at this scale/traffic),
municipality-level filtering as a separate param (admin fields exist in the schema but are
empty for Serbia in GeoNames' current export — noted below).

**Data:** `data/rs-zip.json` was generated by downloading
`http://download.geonames.org/export/zip/RS.zip` (fetched 2026-08-16), unzipping `RS.txt`, and
parsing GeoNames' tab-separated postal-code format (country code, postal code, place name,
admin name/code 1-3, lat, long, accuracy) into a clean array of 1,155 objects with the accuracy
column dropped. The one-off parser script (`scratchpad/geonames/parse.js`, not part of the
deployed app) was run once; the resulting JSON is committed directly. Licensed CC BY 4.0 by
GeoNames.org — attribution is shown on `index.html` and in every API response's `attribution`
field, per license terms.

**Verified during build (2026-08-16):**
- Beograd → postal code `11000` present and correct.
- Novi Sad is listed under `21102` in GeoNames' RS export, not the commonly known `21000` —
  `21000` does not appear anywhere in the dataset. This is genuine upstream data (GeoNames uses
  more granular modern postal codes for some cities rather than the historic round-number
  code), not a parsing bug. `?city=novi%20sad` correctly finds it; `?code=21000` correctly
  returns zero results. Documented as a known quirk on the docs page.
- All 1,155 rows have empty `adminName1/2/3` and `adminCode1/2/3` — GeoNames does not populate
  admin subdivisions for Serbia in this export. Fields are kept in the schema (all API
  consumers get a stable shape) but are currently always empty strings.
