# Gde Na Ručak — SPEC

**MVP:** User picks a city (Beograd, Novi Sad, Niš, Kragujevac) and a budget tier (€ / €€ / €€€). Clicking "Find me a place" filters the seed restaurant list (`data.js`) down to matches and picks one at random, showing its name, cuisine type, neighborhood, and budget tier. A "Spin again" button re-rolls within the same filters, trying to avoid immediately repeating the last pick when more than one match exists. If a city/budget combination has zero matches (e.g. Kragujevac at €€€), the UI shows a friendly empty-state message instead of erroring, and "Spin again" is disabled until a valid pick exists.

**Out of scope for this pass:** addresses/phone numbers (would need live verification this tool can't do), opening hours, user ratings/reviews, "cravings" filter mentioned in the original one-liner (cuisine-type filter would need a much larger, more evenly-distributed dataset to be useful — deferred), map integration.

**Data:** ~25 restaurants across the 4 cities in `data.js`. Every entry is a real, well-known, long-established restaurant/kafana — no invented names. Confidence is meaningfully higher for Beograd (10 entries, all iconic decades-old institutions like Tri Šešira, Znak Pitanja) and Novi Sad (7 entries) than for Niš (5 entries) and Kragujevac (4 entries), where fewer restaurant-level facts met the "confident it's real and currently known" bar — this is a deliberate scope call to avoid fabricating plausible-sounding names for cities the author has thinner knowledge of, rather than an oversight. As a result Kragujevac currently has no €€€ entry; the UI handles that gracefully. This is explicitly framed to the user as a "curated starting set, not exhaustive" — treat the Niš/Kragujevac lists as even more provisional than Beograd/Novi Sad's, and verify locally before relying on any entry.
