# Digital Detox Timer — SPEC

**MVP:** Ships as a web app rather than a browser extension (see `MASTER_TRACKER.md` — the Chrome Web Store's $5 one-time developer fee is out of scope for this sprint). The user maintains a personal list of distracting sites/apps (plain text labels, added/removed freely, persisted in `localStorage`) and sets a focus session length in minutes. Starting a session shows a full-viewport "focus mode" overlay with a large countdown, the blocklist rendered as a reminder, and an "End session early" button. This is honor-system — a webpage genuinely cannot block other tabs or sites — so the value is the visible commitment device, not enforcement. The browser tab title updates every half-second with the remaining time (`MM:SS · Focus`) so the countdown is visible even when the tab isn't focused, and reverts to the page title when the session ends. Every finished session (completed naturally or ended early) is recorded to `localStorage` with start time, planned vs. actual duration, and a completed/abandoned flag — including sessions cut short by closing/refreshing the tab, caught via a synchronous `beforeunload` write. A stats card shows total focus time for the current calendar week (Monday-start) and the current daily streak (consecutive days with at least one *completed* session; today not having one yet doesn't break the streak, matching how most habit trackers count "still on track").

**Out of scope for this pass:** actually blocking or restricting any site/app (technically impossible from a webpage without a browser extension or OS-level tool — see scope note above); syncing the blocklist/history across devices (`localStorage` is per-browser); scheduling recurring "work hours" (the original one-liner's "locks distracting websites during specific work hours" — session start is manual, on-demand only for this MVP); notifications when a session ends (a two-tone beep plays via Web Audio if the tab has audio permission, but there's no push/OS notification).

**Data/content:** none curated — no `data.js` for this idea, since there's nothing to seed; the blocklist and session history are entirely user-generated and stored in `localStorage` under the `digital-detox-timer:blocklist` and `digital-detox-timer:sessions` keys.
